## 逐项定案（用户四问）

1. **同业表标注**：非样式失效（标注格 markup 与 CSS 均正常），是**覆盖不全**——7 列只标 5 列，
   市值/26H1 同比两列整列裸奔；v4.10 零标注告警（工行实证）管不住部分漏报。
   → validate `_check_peers_bestworst` 升级逐列检查，数值列缺标注按列名告警；
   方向性无意义列（市值）在 peers_meta 注明后抑制（fill-schema 承诺的实现侧此前不存在）。
2. **PE 线消失双根因**：(a) E2 stdout 只给近 12 月带月末 PE，5 年窗口模型拿不到 → `_sec_e2` 增
   「全序列」行（约 2KB）；(b) 即使照抄全序列，天齐 29/68 点有效也过不了「过半缺失不画」门槛
   → 图门槛放宽为有效 pe ≥12 点（charts_cycle），validate 告警口径同步且与图同用 `_num` 解析。
3. **户数横标**：`date[2:7]` 截断遇月内多期披露（天齐 2026-07 四期）全渲染成「26-07」→ 碰撞
   自动降精度（同年 MM-DD、跨年 YY-MM-DD）；同截止日双行（上游 20260710 近似重复）图内去重
   保留后写行 + validate 告警。**第二轮用户拍板改季度口径**：`fetch_holders_quarterly` 只取季末
   近 12 期 + 最新点，去重先于截断、环比在干净序列重算；柱宽封顶 72→44。横标降精度保留为兜底。
   **用户前提勘误**（已当面说明）：互动易披露亦真实，问题在「间隔不均」不在「准确性」。
4. **治理块**：用户拍板保持 3-5 块裁剪，补「扣分」状态档（miss 红文案分两档：扣分=已进依据链 /
   关注=不扣分仅跟踪）；validate 校验评分段含扣分项而块内无 miss「扣分」行 → 告警。

## 教训

- **「不炸链路」的承诺必须贯通到渲染层**：取数层的优雅降级（缺键仅 close）若渲染层不做对应
  退化，等于把崩溃推迟到更重的地方爆。跨界面的降级契约要成对写、成对测（本版补了混合态测试）。
- **哨兵循环的尾部段**：`for ... + [哨兵]` 模式对「延伸到结尾的段」必须有显式收尾分支，
  否则最后一段静默丢失——本版两处（PE 分段、亏损底纹）同源。
- **告警口径与实现口径要同源**：validate 用 `is not None`、图表用 `_num`，缝隙里漏掉图文不符；
  同类判定（pe 有效性、户数期数、去重键）应共享同一解析函数。
- **版本号在变更中途重定（4.10.4→4.11.0）会留下 21 处漂移**——版本号应在动笔改注释前定死。
- **手写 HTML 的校验正则必须容忍写法漂移**（class 顺序、全角/半角减号、嵌套括号）——规范形态
  只是最常见形态，不是唯一形态。
