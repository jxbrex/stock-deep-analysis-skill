## 本轮触发：近期报告暴露的 12 条问题

用户从巨石/中兴/豪威/天赐/冠农报告中提出 12 条问题，逐条定位根因后修复。
**最关键的一个发现**：巨石报告（600176，棕色主题、SVG 三轨计分器）根本不是模板产物——
render 因 `gap_html` 表格缺 `.source` 被拒两次后，会话模型绕开 fill→render 管线手写全文 HTML。
用户的第 1/3/5 条（渲染报错、趋势表头对齐、跟踪指标表对齐）都是这一个根因的表象。
管线内报告（中兴等）的表格对齐一直由 `fix_table_alignment` 正常工作兜住。

## 改了什么（问题驱动批）

- **防绕行**：渲染输出尾部嵌入 `<!-- generated by render_report.py v4.3 -->`，SKILL 成稿自检加
  grep 校验；缺 `.source` 的拒渲染报错附修复指引并点名「禁止手写绕行」；SKILL 禁止事项点名
  巨石案例。
- **Hero 双分卡大小不一**：模板 `.hero-tracks` 改 `align-items:stretch` + `.hero-track` 加
  `flex:1 1 0`（原来是 center + min-width，卡片随内容各自撑开）。
- **时机判定小表合计行**：`_tag_timing_table` 给含「合计/时机分」的末行补 `tr.total`，
  模板 `tr.total td` 加粗+浅底。注意没用 `tr:last-child`——无合计行的两行表会误标技术面行。
- **结尾双横线**：`.disclaimer` 去掉 `border-top`（末个 section 卡片边框已承担分隔）。
- **子智能体时有时无的根因**：SKILL.md「默认委派 MANDATORY」与 data-collection.md Step 1.3
  「极少用」自相矛盾，硬门禁文件压制了主文件。两处统一为**条件强制**（用户拍板）：
  peer ≥3 批量取数 + 公告 PDF 下载提表必须委派，其余不委派，定性调研仍禁止。
- **fill 自检坑人命令**：fill-schema 原推荐 `python -c json.load`（与「唯一 Python 调用是渲染
  命令」矛盾，且 Git Bash 下 cmd 反斜杠路径必炸）。render_report.py 新增 **`--check` 模式**
  （解析+评分+地板全预检，退出码 0/2），fill-schema 改为只准用它；补「Git Bash 路径一律正斜杠」。
- **`old_string not found`**：规则早有（先 Read 再 Edit），本轮补镜像提示 + 两条实测经验：
  锚点别跨 `\"` 转义、别从 python repr 输出反推原文（repr 会把反斜杠加倍）。
- **thesis 只有目标价**（中兴实证）：fill-schema 加写作要求+巨石正例；渲染器加信息量地板
  （纯文本 <60 字或剥掉三情景价后 <20 字 → 告警）。
- **deepseek 内容缩水**（中兴/豪威实证，即 v4.2 思考题④）：dim-block 纯文本 <40 字**拒渲染**、
  <80 字告警（用户拍板的折中力度）。合规样本 test_fill_v41.json 的 6 个薄块已加厚到新标准，
  顺手清掉样本里 3 处 v4.2 起就告警的 L1/L3/1D 代号残留。
- **代号转换成本**：scoring.md 维度标题双语化（财务健康（1D）式）+ 新增「维度称呼统一」段——
  思考与正文全程中文名，1A-1F/3A-3C 只作 scores 键与评分表简写。脚本零改动。

## 改了什么（审计底账批：F1/⑤/F3/F4/F6/F7/F8）

- **F1 tushare 缓存**：`ts_call` 透明模块级缓存（键=api+归一化参数）+ `_fin_rng()` 统一财务窗口
  （forensic 7 年/年表 5 年/最新季度 2 年 → 统一 7 年，调用方本地过滤）。附带发现：params 里的
  `fields` 是 no-op（tushare 只认 payload 顶层 fields），缓存键归一化时剔除。实测 600989：
  income/cashflow/balancesheet/fina_indicator 各 1 次请求、daily_basic 2 次（5 年带 vs 最新快照
  无法合并），**每股省 8 次网络往返**，输出不变。调试：`EM_FETCH_DEBUG=1` 打印 net/cache-hit。
- **⑤ 关键假设变更表**（v4.2 思考题⑤）：backtest.md 6.6 硬性要求（相邻两版三情景假设对比，
  假设未变也要显式写明，分数与假设变化不匹配必须解释）；渲染器软校验（review_html 缺假设表 → 告警）。
- **F3/F4/F6 删除**：`_transpose_scenario_table`（-49 行）、`_normalize_class_aliases`（-10 行）、
  `_TIMING_LEGACY`+`_timing_field`（旧键名改显式拒渲染，实测 2B/2C 报错文案正确）。
- **F7**：四个估值映射函数 → `_lookup`/`_lookup_lt` + 四张阈值表常量；`_map_warranted` 的 ≤ 边界
  用 1e-9 偏移精确保留（<0.8/<0.9/<1.0 是严格小于，≤1.1/≤1.2 是含等号，别在下次重构时改丢）。
- **F8**：`_pad_domain`/`_lin_map`/`_ticks` 三个 SVG helper，走廊图与散点图复用。

**F2/F5 评审否决（标记为暂缓，理由已写进底账）**：删表格对齐引擎/删非法转义修复在弱模型
（deepseek）场景下会把「脚本一次修复」变成「模型多次往返且可能修不对」，本轮实证支持保留。
