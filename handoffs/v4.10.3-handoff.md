## 决策记录

- **迟绑定靠模块属性访问继承**：删掉 em_data 的两个动态转发 stub 后，「调用时解析、rebind 可传导」
  的语义并未丢失——`_C.ts_call(...)` 本身就是模块属性访问，每次调用重新查 `em_core.__dict__`。
  故宿主（em_fetch）与四取数块统一写 `_C.ts_call/_C.get`，纯工具（映射/格式化/窗口/错误政策）
  走静态 `from em_core import`。测试 rebind 目标随之从 `em_fetch.*` 迁到 `em_core.*`。
- **`_ts_quiet(label, exc)` 只收政策判定、不收 loader**：六连（fetch_governance×3 / fetch_disclosure /
  fetch_audit / fetch_debt）的「default」全是 None 或无操作，`(label, loader, default)` 形参会空转；
  而 loader 形式要求把每段 try 体塞进嵌套函数并整体重排缩进（diff 大、可读性反降）。改为调用点写
  `except (OSError, RuntimeError) as e: _ts_quiet(label, e)`——两类异常互不继承，合并捕获与原先
  两个顺序 except 完全等价，⚠️ 文案与触发条件逐字节不变（实测计数仍为 6，断言 `>= 5` 未动）。
- **日期窗口 helper 以「发出的请求参数逐字节不变」为第一优先**：`_win_days(n)`/`_win_years(n, end=None)`
  收编 9 处；`_em_kline_monthly` 的 `end="20991231"` 走 `end` 形参收编（否则只能不收）；
  两处**不收**——`fetch_kline_monthly` 的港股月份标签 `{year-N}01`（聚合口径非请求窗口）、
  `fetch_consensus` 的 `today.toordinal()-180`（对已取回全量研报的截断口径）。`_ttm_cutoff` 保留
  原样：它带可注入 `today` 形参（test_02 闰日路径在用），改写需给 helper 加形参或丢测试能力。
- **`_TS_CACHE` 不 memo 化**：它是「内存→磁盘→网络」三级链，memo 只能吃最外层；外层命中带
  `_stat("ts_mem")` + `EM_FETCH_DEBUG` 的 `[cache-hit]` 副作用，锁内二次检查同样计一次 `ts_mem`，
  三级各有独立计数——硬套 memo 必然改掉统计/诊断输出，属越界改动。保持原样（diff = 0）并记录在案。
- **`fetch_forensic` 归 em_finance**：它调 `fetch_audit` + `_pick_latest_per_period`（都在财务块），
  计划原把它放 misc。规则是「块间零横向 import」，两条出路里选「整函数归财务块」——另一条
  （把公开 `fetch_audit` 搬进 em_core）会把 E3 边界搅浑且 em_fetch 的 re-export 指向 core。
- **`_em_dc` / `_daily_basic_latest` 归位 em_core**：前者原计划归 misc，实际被 finance/owner 五处
  调用、**misc 侧零调用者**；后者被 market+finance 共用。两者都是纯工具且被多块共用，按规则归 core。
- **`_sec_e3_hk` 不下沉**：它只剩文案级降级（数据兜底在 `_ts_hk_annual_rows` 内部），无代码级降级可搬；
  同轮修正其文案混血（见「有意行为变化」②）。
- **`_INDEX_CACHE`（score_calibration）不纳入 memo**：形态合规（raise 早于回填），但该文件不在账本
  五套缓存内、目前不 import em_core，为 6 行片段新增模块依赖 + 抽 18 行内联 loader 不划算；
  要收是 1 行 import + 一个嵌套函数的成本（已结转）。
- **`collect_reports` 不递归**：它扫的是 `render_report.py` 的扁平输出目录，递归会**静默扩大校准
  样本集 → 改变校准数字**（数据口径问题，不是诊断问题）；本步只给它加「解析失败提示」（纯 stderr）。
- **`find_prev_report` 哨兵用 NamedTuple + 「恒真须看 .path」警示**：全仓此前无 namedtuple/dataclass，
  选 `PrevFind(NamedTuple)` 是为调用点 `res.path`/`res.status` 自解释；代价（命名元组恒为真，
  不能用真值判断）写进 docstring 并在 CLI/测试里显式查 `.path`。

## 教训与记账

- **工具写出的 UTF-8 无 BOM 会炸 PowerShell**：`deploy.ps1`（含中文）编辑后 BOM 丢失，被 PowerShell
  按 GBK 解析直接报错——已恢复 BOM。**含中文的 .ps1 必须带 BOM，编辑后立刻跑一遍
  `powershell -File scripts\deploy.ps1` 预览验证**。
- **混合行尾文件没法用 Edit 改多行**：em_data.py 头部 LF、主体 CRLF，Edit 工具跨 CRLF 的多行
  `old_string` 一律匹配失败（探针实证：纯 LF ✓、纯 CRLF ✓、混合 ✗）。CRLF 区改动只能用一次性脚本，
  按「行号 + 关键字」双断言定位、逐行沿用原终止符重写，并断言 CRLF/LF 计数只随删行数变化。
- **测试 mock 面迁移要全仓 grep 赋值式补丁**：Step 1 按账本清单改 rebind 点，漏了
  `test_monthly_checkup.py`（它 rebind `em.ts_call` 但不在清单上）——凡改模块归属，先
  `grep -rn "em\.[a-z_]* *=" scripts/` 找所有赋值式 patch，再逐个定归属，别只信账本。
- **「靠模型手工兜错的已知坑」必须下沉取数层**：fina_mainbz 维度合计行 76 缓存里 42 个含（通病非
  个例），此前靠填写方在 note 里手写重算占比兜（云铝/甘李实证）——凡同一数据坑被兜错 ≥2 次，就得
  改取数层而不是继续写提醒；配套教训：**校验告警文案要指向真因而非表象**，segments 合计告警原文只
  「请核对是否漏列分部」，模型据此自造「另 50% 按地区口径」解释，真因（未剔合计行）反而被掩盖。
- **golden 盲区不只在新图字段**：v4.10.2 立下「新增图字段同步进 full_fill」纪律，但**既有图表**（时机
