## 教训

- **「不炸链路」的承诺必须贯通到渲染层**：取数层的优雅降级（缺键仅 close）若渲染层不做对应
  退化，等于把崩溃推迟到更重的地方爆。跨界面的降级契约要成对写、成对测（本版补了混合态测试）。
- **哨兵循环的尾部段**：`for ... + [哨兵]` 模式对「延伸到结尾的段」必须有显式收尾分支，
  否则最后一段静默丢失——本版两处（PE 分段、亏损底纹）同源。
- **告警口径与实现口径要同源**：validate 用 `is not None`、图表用 `_num`，缝隙里漏掉图文不符；
  同类判定（pe 有效性、户数期数、去重键）应共享同一解析函数。
- **版本号在变更中途重定（4.10.4→4.11.0）会留下 21 处漂移**——版本号应在动笔改注释前定死。
- **手写 HTML 的校验正则必须容忍写法漂移**（class 顺序、全角/半角减号、嵌套括号）——规范形态
  只是最常见形态，不是唯一形态。

### 新增待解决（按优先级）

- **A-D1【P1】负利润 + 非 12 个月 horizon → 复数 → TypeError 裸崩**。
  `scoring.py::compute_valuation` L203-204：`central_raw < -1` 时 `(1+central_raw) ** (12/months)`
  在 Python3 返回 complex（实证 central=(-1+0.74j)），`_map_central → _lookup` 的 `val >= t`
  抛 TypeError；`render_report.py` L577 只捕获 ValueError → 裸 traceback 直出。
  方案（三层）：① L204 加守卫 `central_raw > -1` 才年化，否则 `central = central_raw`
  （负中枢本就不该年化——「中枢为负拦截器」按 central_raw<0 判定，年化对负中枢无意义）；
  ② `render_report.py` L577 捕获面扩为 `(ValueError, TypeError)`（采纳审核建议 S2，
  作兜底防线）；③ `validate._check_valuation_scenarios` 对 profit+pe 口径负 profit
  **告警不拒**（困境反转/未盈利合法路径是正常化利润或 mcap 口径，提示模型确认口径即可）。
- **A-D2【P1】三情景跨档倒挂只告警不拒，负离散度被错误上浮**。
  `compute_valuation` L208-209 识别倒挂仅 print；`_check_valuation_scenarios` 只校验
  单情景区间；`_position_steps` L581-582 把 dispersion=-25.2（实证）判为「<40% 低不确定性」
  上浮一档（轻仓→标准仓，方向相反的错误结论）。
  方案：① `_check_valuation_scenarios` 增跨情景顺序硬校验——复用 `_scenario_numbers`
  按 key 取 pess/base/opt 复算 mid，`pess.mid > base.mid 或 base.mid > opt.mid` 拒渲染
  （mcap 口径同式适用）；② `_position_steps` 离散度上浮分支加 `calc["dispersion"] >= 0`
  下限守卫（校验层漏网时的第二道防线）；③ L208 告警文案升级为指向「将被拒渲染」。
- **A-D3【P2】`_check_dim_blocks` 按位置 zip 匹配维度，块乱序时极端分证据校验错配**
