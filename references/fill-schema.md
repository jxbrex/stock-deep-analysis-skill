# fill-data JSON 契约（render_report.py 输入规范）

渲染流程：模型把全部分析内容写成一个 JSON 文件 → `python render_report.py fill.json`
→ 脚本完成评分计算 + 占位符替换 + 校验 + 自动命名输出。**模型不需要碰 HTML 文件本身。**

## JSON 书写硬规则（违反即解析失败）

- **禁止裸反斜杠**：fragment 里任何 `\` 在 JSON 字符串中必须写成 `\\`（`\ `、`\P` 等都是非法转义）。
  表头、分隔符一律用全角 `＼` 或 `/`，从源头避开反斜杠（见 9 矩阵示例）。
- 字符串内换行用 `\n`，不要直接回车；双引号用 `\"` 或改用中文引号「」。
- **字符串一律双引号，禁止 Python 单引号**——分段 append 时尤其容易把字段写成
  `'key': 'value'`（Python 字典习惯），json.load 直接失败（腾讯 2026-08-23 实证）。
- fragment 内嵌 HTML 的属性引号：`class="..."` 需 `\"` 转义，写单引号 `class='...'` 也可以——
  渲染器入库时自动把 class 单引号归一为双引号（v4.4 起，万华 2026-08-26 实证 258 处），
  不影响校验与输出；报错/告警文案里一律以双引号显示。
- **【…】 只允许黄灯类别标注**（如【b 行业与政策环境】，以单个 a-d 字母开头）；
  其他用途一律用（）或「」——其余【…】会被渲染器判为未替换占位符而拒渲染。
- 修补已写盘的 fill：**先 Read 再 Edit**（脚本/外部过程改过的文件直接 Edit 会被
  staleness 守卫拦截；报 `old_string not found` 就是你跳过了 Read——先 Read 再重发 Edit）；
  分段写盘时按字段边界切段。**Edit 锚点选不含 `\"` 转义的纯文本片段**（单行长 JSON 里
  锚点跨转义引号极易失配；也不要从 python repr 输出反推原文，repr 会把反斜杠加倍）。
  大段返工不要逐点 Edit——用 Write 重写该字段更快更稳。
- 写完后的自检**只有一条合法命令**：`python "<技能目录>/scripts/render_report.py" "_fill_[代码].json" --check`
  （JSON 解析 + 评分计算 + 内容地板全预检，退出码 0 才能渲染）。**禁止手写 `python -c` 内联自检**
  （Windows 控制台引号/编码坑，中兴 2026-08-24 实证；本环境 shell 是 Git Bash，路径一律用正斜杠，
  `D:\...` 反斜杠路径在 bash 下不存在）。
- render_report.py 已带非法转义自动修复（兜底+告警），但不保证覆盖所有写法，仍以写对为准。

## 顶层字段

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `company` | ✓ | 公司名（如 "宝丰能源"） |
| `code` | ✓ | 代码（如 "600989"；港股 5 位数字如 "06082"） |
| `currency` | 可选 | 股价/目标价的币种单位（默认 "元"；港股填 "港元"，其他币种同理）。模板单位与情景表目标价行均由脚本统一替换 |
| `date` | ✓ | 报告日期，必须严格 YYYY-MM-DD 格式（不匹配即拒渲染） |
| `subtitle` | ✓ | 副标题（行业标签 · 一句话定位）。**禁止包含报告日期**——模板 Hero 自动追加「｜报告日期：date」，手写会渲染出两次（渲染器会防御性剥离并告警，仍以写对为准） |
| `scores` | ✓ | **质量层** 9 维得分对象：`{"1A":8.0,"1B":7.0,"1C":8.0,"1D":8.0,"1E":7.0,"1F":7.5,"3A":7.5,"3B":8.0,"3C":7.0}`（v4.0：L1 六维 1A-1F + L3 三维 3A-3C；2A 估值独立成估值分） |
| `valuation_score` | 无需填写 | **估值分永远由脚本计算**（四件套，见 `valuation_inputs`），fill 里不再需要该字段——填了也被脚本计算值覆盖（差值 >0.11 时告警提示删除） |
| `valuation_inputs` | ✓ | **估值分四件套输入（必填，缺键拒渲染）**：`{"pe_ttm":13.5,"pe_band":[14.5,15.5],"div_yield":1.6,"risk_free":1.7}`（pe_ttm 现价 PE、pe_band 合理带 [低,高]、div_yield 税后股息率 %、risk_free 无风险利率 %）。脚本据此自动算估值分，并在 7 估值章末尾汇总卡生成四件套明细（6 章只汇总质量分，不重复估值/时机明细）。**可选 `metric_label`**（如 "P/NAV"、"P/rNPV"、"P/EV"、"经调整PE"）：行业附录市值口径（见 `scoring.md`「市值口径三情景」节）下替换过程卡 PE(TTM) 标签，pe_ttm/pe_band 数值语义随之变为对应比率，映射公式不变 |
| `weights` | 可选 | 质量层维度权重覆盖（L1 六维层内权重之和=100；L3 三维层内权重之和=100。分型调整时用） |
| `layer_share` | 可选 | 层占比覆盖：`{"L1":85,"L3":15}`（两值之和=100。分型调整时用） |
| `timing_scores` | ✓ | **时机层**得分对象：`{"筹码面":2.5,"技术面":6.0}`（旧键名 2B/2C 兼容已移除，误用直接拒渲染）。两维各自**中性 5 分起始 + 清单信号加减**（评分锚见 `scoring.md` 时机分一节），禁止凭感觉给分；**缺键或缺维度即拒渲染（筹码面/技术面缺一不可，不接受缺维按 0 计）** |
| `timing_weights` | 可选 | 时机层权重覆盖，默认 `{"筹码面":67,"技术面":33}`，和必须=100 |
| `yellow_deductions` | ✓ | **黄灯扣分明细**数组：`[{"label":"关联交易占比过高","points":0.6}, ...]`；无扣分填 `[]`。**硬校验：键缺失即拒渲染（无扣分必须显式填 `[]`）；单项 >1、累计 >2 或 points 为负 → 拒渲染**（累计超上限按规则应升红灯；负扣分等于变相加分、绕过上限）；质量分扣完后下限 0 |
| `red_deductions` | 可选 | **1D 红旗扣分明细**数组：`[{"item":"现金含量连续2年<0.7","points":1}, ...]`；**每项 points 上限 1（超出拒渲染）；points 为负同样拒渲染**。脚本从 `scores["1D"]` 中减去合计（下限 0），并在 6 质量分汇总表中单列一行展示 |
| `red_flag` | 条件 | **红灯标记**：命中红灯填具体项（如 "审计意见非标：无法表示意见"），未命中省略或填 `""`。**熔断硬校验：red_flag 非空时 `position_html` 必须包含「不建议参与」，否则拒渲染** |
| `thesis_html` | ✓ | Hero 一句话结论（**为空即拒渲染**），**全文提纲挈领句 = 论点 + 关键证据 + 三情景价 + 操作结论**（含 `<span class="scenario-pess/base/opt">` 三情景价）。正例：「全球玻纤龙头+AI电子布第二曲线，中报净利+73.9%兑现高景气，但股东户数单季暴增254.6%且PE处5年90%分位——好公司、坏价格未变。三情景目标价 15.7/37.5/61.8 元，年化中枢 -10.9%——回避当前价，等 25-29 元观察区」。**只塞三个目标价 = 不合格**（中兴 2026-08-24 实证；纯文本 <60 字或剥掉三情景价后 <20 字 → 告警）。**一致性硬校验：三个手写价与脚本按 `valuation` 算出的情景中枢价对比，相对偏差 >2% 且绝对差 >0.1 → 拒渲染**（报出两组数值）；span 类名不齐仍是告警 |
| `price` / `mcap` / `pe_ttm` | ✓ | Hero 指标卡数值（纯数字字符串）；**price 缺失或无法解析为数字即拒渲染** |
| `price_sub_html` / `mcap_sub` / `pe_sub` | ✓ | 指标卡 sub 行（可含 `<span class="up/down">`） |
| `horizon` | ✓ | 目标价时间维度（如 "12个月"） |
| `target_range` / `target_sub_html` | ✓ | 目标价区间卡。**target_range = 基础情景目标价区间**（如 "86-93"），脚本按 `valuation` 自算，不一致按计算值覆盖并告警——**不是三情景全区间**（万华 2026-08-26 实证误填悲观~乐观全区间被覆盖）；target_sub_html 写该区间对应现价的空间说明 |
| `conclusion_html` | ✓ | 1 核心结论正文。**四段固定**（连续 `<p>`，`<strong>` 小标题开头）：①关键优势（2-3 个具体优势+数据）→ ②关键弱点（2-3 个不回避的弱点+数据）→ ③当前市场认知（卖方假设带来源+市场定价隐含预期，与 8 呼应）→ ④核心投资逻辑（本文核心论点+可观测证伪条件+路径判断）。**禁止 `.metric-row`/评分表/判词卡**——评分数字在 Hero 与 section-meta 已呈现，正文只写文字。命中红灯 → 首部 `.danger-card`（脚本 `RED_FLAG_HTML` 自动注入）；红旗命中≥2 项 → 首句"利润真实性存疑"；显著情绪/筹码风险 → 末尾 `.warning-card`。**内容地板：纯文本 <200 字拒渲染**。**骨架见下方「核心结论四段骨架」** |
| `p0_html` | ✓ | P0 关键利润驱动：`<span class="section-tag">分型：XX股</span>` + 识别特征一段（分型理由/层占比/估值方法）→ 引出关键变量一句 → 敏感性表（关键变量/变动幅度/年利润影响/弹性等级，★标注弹性）→ `.source` → `.info-card`「为什么 X 是第一变量」（解释杠杆最大原因 + 三情景如何围绕它定义）。参照腾讯控股 2026-08-08 报告 P0 |

| `l4_html` | ✓ | **L4 风险双层**正文片段（红灯 checklist + 黄灯扣分表 + 损失预演卡；损失预演卡标题固定写「损失预演」，禁止用英文 Pre-mortem） |

## 片段内 HTML 骨架（模型在 fragment 里照用）

**核心结论四段骨架（`conclusion_html` 专用，顺序固定 ①→④，参照腾讯控股 2026-08-08 报告）：**

```html
<p><strong>关键优势：</strong>……（2-3 个具体优势，附数据，对应质量分高分维度，用分号连接）</p>
<p><strong>关键弱点：</strong>……（2-3 个不回避的弱点，附数据，对应质量分低分维度/黄灯，用分号连接）</p>
<p><strong>当前市场认知：</strong>……（卖方一致预期带来源日期 + 市场定价隐含假设，与 8 预期差档位呼应）</p>
<p><strong>核心投资逻辑：</strong>……（本文核心论点一句 + 可观测证伪条件 + 路径判断：未来 1-3 个月市场最可能先交易哪个变量）</p>
<div class="warning-card"><strong>情绪与筹码提示：</strong>……（条件触发，显著情绪/筹码风险才加）</div>
```

**四段红线**：
- 四段是**连续 `<p>` 段落**，**不用 `<ul>` 列表**，每段内多个要点用分号或句号连接。
- **禁止 `.metric-row` 三块评分卡、9 维评分表、三轨判词卡**——评分数字在 Hero 与 section-meta 已呈现，正文只写文字（中芯国际两次实证）。
- 关键优势/关键弱点各 ≥2 个具体点、每条带数据，**禁止空泛形容词**；弱点不回避，必须点名对应维度/黄灯。
- 当前市场认知必须引用具体卖方（带来源/日期）或写明"未找到卖方覆盖"，与 8 档位一致。
- 核心投资逻辑的证伪条件必须可观测；路径判断写"未来 1-3 个月交易哪个变量"，不能复读估值结论。

**维度块（L1-L4 每个维度一个）：**
```html
<div class="dim-block">
  <div class="dim-header">
    <span class="dim-name">3.1 赛道与宏观</span>
    <span class="dim-weight">7%</span>
    <span class="score-line" style="margin-left:auto;margin-bottom:0;"><span class="badge badge-green">8.0</span></span>
  </div>
  <p>分析正文……</p>
  <div class="verdict">一句话判词。</div>
</div>
```

**薄块正例（结构样板，内容为示意）**：正文 `<p>` 按「判词 → 论据 → 对比 → 收口」四拍写，
每个维度块 200+ 字，论据必须带具体数字与出处（巨石/金诚信报告即此结构，DeepSeek 式一句话块属不达标）：

```html
<p><strong>判词：</strong>矿山服务龙头，海外收入占比 72% 是核心阿尔法。
<strong>论据：</strong>2025 年报海外毛利 31.2 亿（+24%），单体矿山服务合同平均存续 8.5 年，续约率 91%（年报 P17）；
<strong>对比：</strong>国内同业海外占比均值仅 18%，公司 ROIC 五年均值 18.4%，高同业 8-10pct；
<strong>收口：</strong>护城河在长期服务协议锁定，而非单次勘探能力——铜价下行期续约率是唯一要先盯的先行指标。</p>
```

**徽章色规则**：≥7.0 → `badge-green`；4.0-6.9 → `badge-orange`；<4.0 → `badge-red`。

**层小结（每层末尾）**：`<div class="layer-summary"><strong>L1小结：</strong>……</div>`

**L4 扣分行**：`<span class="deduction">−3 扣分原因……</span>`（`.deduction` 是块级元素，**两条之间不要加 `<br>`**，渲染器会直接隐藏这种多余换行；四类顺序固定 a→b→c→d，乱序会触发渲染器告警）

**盈利质量红旗行**（1D 财务健康，四项检查：现金含量/应收/存货/毛利率；审计意见不在此列，供 L4 红灯 a 判定）：每行用三态 span 包裹行首（✓绿 / ✗红 / △橙）：

```html
<span class="flag-ok">✓ 利润现金含量</span>（最低 1.20，五年均 >1）<br>
<span class="flag-bad">✗ 应收账款周转</span> 恶化（12→16 天，+33%）<br>
<span class="flag-na">△ 毛利率</span> 35.1%（待与同业对照）
```

**提示卡**：`.info-card`（蓝/逻辑说明）`.warning-card`（橙/警示）`.danger-card`（红/致命警告+损失预演）

**变更高亮 `.rev`**（回测模式专属，淡黄底）：只标三类——**评分变化**（旧→新+一句原因）、
**被验证/被证伪的关键假设**、**新增重大变量**。用法：行内 `<span class="rev">2026E净利 930→985亿</span>`，
表格整格 `<td class="rev">`。满屏高亮=没高亮，宁缺毋滥。

**指标卡条**（7 三指标卡、Hero 数据卡同款骨架；**内层类名是 `label`/`value`/`sub`，
不要自创 metric-label/metric-value——渲染器虽会归一，但写对才是自描述**）：

```html
<div class="metric-row">
  <div class="metric-card">
    <div class="label">年化中枢期望收益</div>
    <div class="value up">+21.0%</div>
    <div class="sub">基础中值 472 ÷ 现价 390.4 − 1（12个月）</div>
  </div>
  <div class="metric-card">
    <div class="label">赔率（上行/下行）</div>
    <div class="value">2.32</div>
    <div class="sub">(614−461.6)÷(461.6−396)；&gt;1.5 为良好不对称</div>
  </div>
  <div class="metric-card">
    <div class="label">情景离散度</div>
    <div class="value down">46.8%</div>
    <div class="sub">(乐观中值−悲观中值)÷现价；&gt;90% 高发散降仓一档</div>
  </div>
</div>
```

`value` 着色：正收益/利多 `class="value up"`（绿），负值/利空 `class="value down"`（红），中性不加。

**数据来源标注**：`<span class="source">数据来源：……</span>`（每张数据表下方必须有）

**表格**：`<div class="table-scroll"><table>…</table></div>`，数字列 `<td class="num">`，居中列 `<td class="center">`。
**表头必须与数据列同对齐**：数字列表头 `<th class="num">`、居中列表头 `<th class="center">`（与对应 `<td>` 同规则）；
纯文字列表头保持默认左对齐，不要加类。
**渲染器已加对齐自动修正**（按列统计 td 类给 th 配对，行头 th/rowspan/colspan 均处理）——
模型写错表头类不再影响最终输出，但仍建议按规则写对（保持 fragment 自描述）。
**数值列（num 列）内的 td 也会被统一**：数字/含数字短值/短标记（如"基础""12个月"）统一右对齐；
全文字行（如"核心业务"行）与长文格（含句读或超 4 字纯文字，如"触发条件"）去类左对齐。
模型最省心的做法：**数据格一律不加类，交给渲染器**。
**宽表首列冻结**（≥5 列的数据表，如 9 同业当前指标表必用）：`<table class="freeze-first">`——窄屏横向滚动时首列常驻。

**数字千位符**：金额/户数类数值 ≥1000 必须带千位符（`2,949.2 亿`、`9,536.8 亿`、`188,153 户`）；
年份（2025）、PE/PB 倍数、百分比、股价、EPS、评分**不加**。em_fetch 输出已带千位符，fragment 手写数字照此规则。

**数字列不混文字值（MANDATORY）**：`class="num"` 的列里，每个单元格都应是数字或含数字的短值
（如 `-2.1%`、`1,300 亿`）。纯文字值（如「双正增长」）会被脚本判为文字格左对齐，和同列数字
右对齐打架，视觉错乱（中国移动/新华保险已实证）。两种处理二选一：① 文字值改成数字表达
（「双正增长」→「同口径 +X%」）；② 该列整体改为文字列（去掉 `num` 类）。禁止「数字列里混一句文字」。
含箭头的区间值（如 `→ 85+ 元`）也会被特殊处理，与纯数字同列时同样错乱——区间值一律用
`38-55 元` 这种纯数字写法，不要加箭头。

**估值-质量散点图**（9 同业对比）：填顶层 `peers_plot` 字段，脚本生成直角坐标系散点图
（横轴 PE、纵轴 ROE，每家同业一个精确点位，目标公司钢蓝高亮，3×3 分带背景）。
**坐标/刻度/标签位置全部由脚本计算，模型不要手写 SVG 或估算像素。**
**已填 `peers_plot` 就不要再写 matrix-table**——两图并存冗余，渲染器检测到会直接删除手写九宫格并告警。

**估值-质量矩阵表（兜底）**：仅当 `peers_plot` 无法给出（如同业数据不全）时，
在 `peers_html` 里写 `<table class="matrix-table">` 3×3 表格：行=ROE 高(>15%)/中(8-15%)/低(<8%)，
列=PE 低/中/高（阈值按行业带自定），单元格写「公司名(ROE%/PEx)」、空位填 —；
表头**不用加任何类**，目标公司格用 `class="target"`。

**3年趋势表**（9 同业对比）：方向标注**一律用文字**（升/降/缓升/缓降/大升/大降/平），
**不用单个箭头**（↑↓ 不直观）。幅度约定：|Δ|<0.5pct → 平；0.5-2pct → 缓升/缓降；
2-5pct → 升/降；>5pct → 大升/大降。方向词用 `<span class="up/down">` 着色，
**颜色按指标语义**（ROE/毛利率/净利率：升绿降红；负债率：降绿升红）：

```html
<tr><td>ROE变化</td><td>22.1%→20.0%（<span class="down">缓降</span>）</td><td>13.1%→19.4%（<span class="up">升</span>）</td><td>…</td></tr>
<tr><td>负债率变化</td><td>70.6%→61.9%（<span class="up">降</span>）</td><td>60.4%→64.2%（<span class="down">升</span>）</td><td>…</td></tr>
```

**估值三情景**（7）：**必填顶层 `valuation` 字段**——脚本自动生成目标价走廊（竖向柱）+
三情景对比表 + 三指标卡条（年化中枢/赔率/离散度），全部数字脚本计算（EPS=profit÷shares、
目标价=profit×PE÷shares、中枢/赔率/离散度公式见 SKILL.md Phase 3），类名写死杜绝幻觉。
`valuation_html` 正文只写：估值方法声明、PE 校准逻辑 info-card、条件性 DCF 表/概率提示——
**不要再手写三情景表和三指标卡**（脚本生成版在前，手写会重复）。
仅当无法给出结构化假设时，才退化为手写表格（scenario-table 类）+ 手写 `scenarios` 区间。

**三情景对比表（兜底手写）**：指标在行、情景在列（禁止反过来），`<table class="scenario-table">`
首列指标名不换行；行序=时间维度/触发条件/净利/EPS/PE/目标价/较现价；数值行 `<td class="num">`，
纯文字行（时间维度/触发条件）不加类，情景列表头 `th class="center"`。
**渲染器已加方向自动校正**：检测到"情景在行"的旧写法会自动转置并告警，但仍建议按规则写对。

## 评分计算规则（脚本执行，模型不要手算）

- **质量层（L1/L3）**：层分 = Σ(维度分×层内权重) ÷ 100；不考虑风险质量分 = L1 层分×L1占比 + L3 层分×L3占比
- **1D 红旗扣分**：`red_deductions` 合计从 `scores["1D"]` 中先行扣减（下限 0），再参与 L1 层分计算
- **质量分（最终）** = 不考虑风险质量分 − 黄灯扣分合计（`yellow_deductions` 的 points 求和），下限 0
- **估值分** = 脚本按 `valuation_inputs` 四件套计算（权重公式与判读的唯一权威见 `scoring.md`
  估值分节），**永远脚本计算，fill 里的 `valuation_score` 填了也被覆盖**
- **时机分** = Σ(时机维度分×权重) ÷ 100（筹码面 67% + 技术面 33%）
- 各层内权重之和≠100、layer_share 之和≠100 → 脚本报错拒绝渲染
- scores 缺质量层维度 → 脚本报错列出缺失键
- 徽章色脚本自动按分数分配；**三轨判词、决策矩阵落位、调节轨迹、最终仓位结论全部由脚本生成**
  （11 章末三轨判定与仓位结论卡；调节优先级与档位序列见 scoring.md 决策主轴节，报告不展开）

## 拒渲染硬校验清单（内容地板，v4.1 起）

以下任一条不满足即报错退出，不生成报告：

- `valuation_inputs` 缺失或四键（pe_ttm/pe_band/div_yield/risk_free）不全；
- `valuation` 缺失，或三情景缺 pess/base/opt，或某情景缺 profit+pe 区间（或 mcap 市值区间）/ horizon，或口径混用/双填/mcap 区间非法；
- `timing_scores` 缺失或缺维度（筹码面/技术面缺一即拒）；`yellow_deductions` 键缺失（无扣分必须显式填 `[]`）；`thesis_html` 为空；`price` 缺失或无法解析为数字；`date` 不匹配 YYYY-MM-DD；
- 黄灯/红旗 `points` 为负值（负扣分 = 绕过上限）；`valuation.shares` ≤0；利润口径 PE 区间倒挂（高<低）或为负；
- 黄灯扣分单项 >1 或累计 >2（应升红灯）；`red_deductions` 单项 >1；
- `red_flag` 非空但 `position_html` 不含「不建议参与」；
- `thesis_html` 三情景手写价与脚本计算中枢价相对偏差 >2% 且绝对差 >0.1；
- `conclusion_html` 纯文本 <200 字；`position_html` 纯文本 <100 字；
- `l1_html` 的 dim-block <6 个；`l3_html` 的 dim-block <3 个；`peers_html` 不含 `<table>`；
- 任何章节 html 字段内含 `<table>` 但 `class="source"` 出现次数 < 表格数（报错指明字段）。
