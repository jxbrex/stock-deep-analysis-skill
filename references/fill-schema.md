# fill-data JSON 契约（render_report.py 输入规范）

渲染流程：模型把全部分析内容写成一个 JSON 文件 → `python render_report.py fill.json`
→ 脚本完成评分计算 + 占位符替换 + 校验 + 自动命名输出。**模型不需要碰 HTML 文件本身。**

**数据直填第一原则（防幻觉总纲）**：凡有 em_fetch 出处的数字——`quote`/`valuation_inputs`
（E1 落盘）、`timing` 技术面信号、`pe_history` 的 p25/p75、`price_history` 月末 PE、
`segments`（E6）、`holders`（E4）、`consensus`（E5）——**一律照抄 em_fetch 输出或落盘
JSON 原样回填，禁止手估、手算、凭记忆补**。各字段的直填来源见顶层字段表对应行。

## JSON 书写硬规则（违反即解析失败）

- **禁止裸反斜杠**：fragment 里任何 `\` 在 JSON 字符串中必须写成 `\\`（`\ `、`\P` 等都是非法转义）。
  表头、分隔符一律用全角 `＼` 或 `/`，从源头避开反斜杠（见 9 矩阵示例）。
- 字符串内换行用 `\n`，不要直接回车；双引号用 `\"` 或改用中文引号「」。
- **字符串一律双引号，禁止 Python 单引号**——分段 append 时尤其容易把字段写成
  `'key': 'value'`（Python 字典习惯），json.load 直接失败。
- fragment 内嵌 HTML 的属性引号：`class="..."` 需 `\"` 转义，写单引号 `class='...'` 也可以——
  渲染器入库时自动把 class 单引号归一为双引号（v4.4 起自动归一），
  不影响校验与输出；报错/告警文案里一律以双引号显示。
- **【…】 只允许黄灯类别标注**（如【b 行业与政策环境】，以单个 a-d 字母开头）；
  其他用途一律用（）或「」——其余【…】会被渲染器判为未替换占位符而拒渲染。
- 修补已写盘的 fill：**先 Read 再 Edit**（脚本/外部过程改过的文件直接 Edit 会被
  staleness 守卫拦截；报 `old_string not found` 就是你跳过了 Read——先 Read 再重发 Edit）；
  分段写盘时按字段边界切段。**Edit 锚点选不含 `\"` 转义的纯文本片段**（单行长 JSON 里
  锚点跨转义引号极易失配；也不要从 python repr 输出反推原文，repr 会把反斜杠加倍）。
  大段返工不要逐点 Edit——用 Write 重写该字段更快更稳。
- 渲染成功后 fill 与 E1 落盘由 render 自动归档到报告目录 `_archive/`（v4.10 起，不再是删除）——
  修补已归档的旧 fill 请从 `_archive/` 取回原件再改。
- 写完后的自检**只有一条合法命令**：`python "<技能目录>/scripts/render_report.py" "_fill_[代码].json" --check`
  （JSON 解析 + 评分计算 + 内容地板全预检，退出码 0 才能渲染）。**禁止手写 `python -c` 内联自检**
  （Windows 控制台引号/编码坑；本环境 shell 是 Git Bash，路径一律用正斜杠，
  `D:\...` 反斜杠路径在 bash 下不存在）。
- render_report.py 已带非法转义自动修复（兜底+告警），但不保证覆盖所有写法，仍以写对为准。

## 顶层字段

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `company` | ✓ | 公司名（如 "宝丰能源"） |
| `code` | ✓ | 代码（如 "600989"；港股 5 位数字如 "06082"） |
| `currency` | 可选 | 股价/目标价的币种单位（默认 "元"；港股填 "港元"，其他币种同理）。模板单位与情景表目标价行均由脚本统一替换 |
| `date` | ✓ | 报告日期，必须严格 YYYY-MM-DD 格式（不匹配即拒渲染） |
| `subtitle` | ✓ | 副标题（行业标签 · 一句话定位）。**禁止包含报告日期**——模板 Hero 自动追加「｜报告日期：date」，手写会渲染出两次 |
| `scores` | ✓ | **质量层** 9 维得分对象：`{"1A":8.0,"1B":7.0,"1C":8.0,"1D":8.0,"1E":7.0,"1F":7.5,"3A":7.5,"3B":8.0,"3C":7.0}`（v4.0：L1 六维 1A-1F + L3 三维 3A-3C；2A 估值独立成估值分） |
| `valuation_score` | 无需填写 | **估值分永远由脚本计算**（四件套，见 `valuation_inputs`），fill 里不再需要该字段——填了也被脚本计算值覆盖 |
| `valuation_inputs` | ✓ | **估值分四件套输入（必填，缺键拒渲染）**：`{"pe_ttm":13.5,"pe_band":[14.5,15.5],"div_yield":1.6,"risk_free":1.7}`（pe_ttm 现价 PE、pe_band 合理带 [低,高]、div_yield 税后股息率 %、risk_free 无风险利率 %）。脚本据此自动算估值分，并在 7 估值章末尾汇总卡生成四件套明细（6 章只汇总质量分，不重复估值/时机明细）。**可选 `metric_label`**（如 "P/NAV"、"P/rNPV"、"P/EV"、"经调整PE"）：行业附录市值口径（见 `scoring.md`「市值口径三情景」节）下替换过程卡 PE(TTM) 标签，pe_ttm/pe_band 数值语义随之变为对应比率，映射公式不变 |
| `weights` | 可选 | 质量层维度权重覆盖（L1 六维层内权重之和=100；L3 三维层内权重之和=100。分型调整时用） |
| `layer_share` | 可选 | 层占比覆盖：`{"L1":85,"L3":15}`（两值之和=100。分型调整时用） |
| `timing_scores` | ✓ | **时机层**得分对象：`{"筹码面":2.5,"技术面":6.0}`（键名只认筹码面/技术面，旧键名 2B/2C 已移除）。两维各自**中性 5 分起始 + 清单信号加减**（评分锚见 `scoring.md` 时机分一节），禁止凭感觉给分；**缺键或缺维度即拒渲染（筹码面/技术面缺一不可，不接受缺维按 0 计）** |
| `timing_weights` | 可选 | 时机层权重覆盖，默认 `{"筹码面":67,"技术面":33}`，和必须=100 |
| `yellow_deductions` | ✓ | **黄灯扣分明细**数组：`[{"label":"关联交易占比过高","points":0.6}, ...]`；无扣分填 `[]`。**硬校验：键缺失即拒渲染（无扣分必须显式填 `[]`）；单项 >1、累计 >2 或 points 为负 → 拒渲染**（累计超上限按规则应升红灯；负扣分等于变相加分、绕过上限）；质量分扣完后下限 0 |
| `red_deductions` | 可选 | **1D 红旗扣分明细**数组：`[{"item":"现金含量连续2年<0.7","points":1}, ...]`；**每项 points 上限 1（超出拒渲染）；points 为负同样拒渲染**。脚本从 `scores["1D"]` 中减去合计（下限 0），并在 6 质量分汇总表中单列一行展示 |
| `red_flag` | 条件 | **红灯标记**：命中红灯填具体项（如 "审计意见非标：无法表示意见"），未命中省略或填 `""`。**熔断硬校验：red_flag 非空时 `position_html` 必须包含「不建议参与」，否则拒渲染** |
| `thesis_html` | ✓ | Hero 一句话结论（为空 → 告警不拒），**全文提纲挈领句 = 论点 + 关键证据 + 三情景价 + 操作结论**（含 `<span class="scenario-pess/base/opt">` 三情景价）。正例：「全球玻纤龙头+AI电子布第二曲线，中报净利+73.9%兑现高景气，但股东户数单季暴增254.6%且PE处5年90%分位——好公司、坏价格未变。三情景目标价 15.7/37.5/61.8 元，年化中枢 -10.9%——回避当前价，等 25-29 元观察区」。**只塞三个目标价 = 不合格**（纯文本 <60 字或剥掉三情景价后 <20 字 → 告警）。**一致性硬校验：三个手写价与脚本按 `valuation` 算出的情景中枢价对比，相对偏差 >2% 且绝对差 >0.1 → 拒渲染**；span 类名不齐仅告警 |
| `price` / `mcap` / `pe_ttm` | ✓ | Hero 指标卡数值（纯数字字符串）；**price 缺失或无法解析为数字即拒渲染** |
| `quote` | 建议 | **E1 落盘防伪（神华 601088 现价造假事故修复）**：`{"source_file":"_em_600989_quote.json","date":"2026-08-28"}`——source_file 指向 `em_fetch --out` 落盘的 E1 JSON；渲染器读取该文件并比对 `price`/`pe_ttm`，**偏差 >1% 拒渲染**（与估值分四件套同级），文件读不到同样拒渲染（防伪链断裂不放行）。**v4.8 扩展到四件套**：`valuation_inputs.pe_ttm` 与落盘 pe_ttm 偏差 >1% 拒；`pe_band` 与落盘历史带完全无交集拒（部分重叠正常）；`risk_free`/`div_yield` 不做硬比对（港股 div_yield 不机械比对；手工估算/税后折算口径须在 .source 注明）。行业口径（`metric_label` 非空）下 pe 两项比对跳过。fill `date` ≥ 2026-09-02 起缺 quote 即拒渲染（此前存量 fill 仅告警豁免），新报告必配。落盘 JSON 另含 `timing`（现价/MA60/MA120/52 周高低，日线序列计算）——**11 章时机判定小表的技术面信号一律取自该字段，禁止手估**（神华假 MA60 同源修复） |
| `price_sub_html` / `mcap_sub` / `pe_sub` | ✓ | 指标卡 sub 行（可含 `<span class="up/down">`） |
| `horizon` | ✓ | 目标价时间维度（如 "12个月"） |
| `target_range` / `target_sub_html` | ✓ | 目标价区间卡。**target_range = 基础情景目标价区间**（如 "86-93"），脚本按 `valuation` 自算，不一致按计算值覆盖——**不是三情景全区间**（误填成悲观~乐观全区间会被覆盖）；target_sub_html 写该区间对应现价的空间说明 |
| `conclusion_html` | ✓ | 1 核心结论正文。**四卡固定**（v4.9.1 补充修订二：`.concl-grid` 2×2 结论卡网格，顺序 row-major ①②/③④）：①关键优势（恰 3 条壁垒短语+括注数字锚）→ ②关键弱点（2-3 条不回避的弱点+括注数据）→ ③当前市场认知（恰 2 条：卖方假设带来源日期 / 定价隐含假设，与 8 呼应）→ ④核心投资逻辑（恰 3 条固定槽位：论点 / 可观测证伪条件 / 路径判断=未来 1-3 个月市场最可能先交易哪个变量）。**四卡统一 `<ul>` 短列表**（补充修订四：每条 ≤12 字短语 + 至多一个全角括注 ≤15 字（数字/日期/来源），括注不加类；不带展开论述——论证由被引章节承载），每卡=`.concl-head` 卡头 + `<ul>` 短列表 + `.concl-ref` 卡尾「详见 X 章」锚索引（固定映射：优势→`#s3`／弱点→`#s5`（财务弱点可并引 3.4）／市场认知→`#s8`／投资逻辑→`#s7`·`#s11`；只链无条件章节，不链 s10/s12）；浓缩省略的信息由被引章节承载，不在结论章重复。**禁止 `.metric-row`/评分表/判词卡**——评分数字在 Hero 与 section-meta 已呈现，正文只写文字。命中红灯 → 首部 `.danger-card`（脚本 `RED_FLAG_HTML` 自动注入）；红旗命中≥2 项 → 首卡首句"利润真实性存疑"；显著情绪/筹码风险 → 末尾 `.warning-card`。**内容地板：纯文本 <120 字拒渲染**（补充修订四下调——四卡 ul 短列表化后原 200 字地板会误伤合规卡）。**骨架见下方「核心结论四卡骨架」** |
| `p0_html` | ✓ | P0 关键利润驱动：`<span class="section-tag">分型：XX股</span>`（**独占一行**——标签后必须另起 `<p>`，禁止识别特征直接跟在 span 后）→ 识别特征一段（分型理由/层占比/估值方法）→ 引出关键变量一句 → 敏感性由顶层 `sensitivity` 字段承载（脚本生成龙卷风图，含变动幅度/净利影响%/金额影响；写了字段就不要再手写敏感性表——图替代表）→ 驱动卡由顶层 `drivers`/`driver_verdict` 字段承载（v4.11.3 起；**p0_html 不再手写**「为什么 X 是第一变量」info-card——判词横条由 driver_verdict 脚本生成）。参照腾讯控股 2026-08-08 报告 P0。**变量命名规范（v4.9，青啤「①吨价/产品结构（第一变量）」难读实证）**：变量名只放一个概念——驱动因素写正文不进名字（错：吨价/产品结构 → 对：吨价（啤酒平均售价），「靠高端化拉动」写进解释句）；行业黑话首次出现必须白话括注（吨价/批价/量价齐升等）；「（第一变量）」是龙卷风图排序标签，正文枚举不再重复贴 |

| `l4_html` | ✓ | **L4 风险双层**正文片段（**红灯 hero 三卡**（v4.9.1 补充修订二，章首固定，骨架见下方「红灯 hero 卡骨架」）+ **黄灯扣分明细表**（v4.10 起只列 points>0 的类别行，无扣分类别不入表、表末一句兜底，骨架见下方「L4 黄灯扣分明细」）+ **损失预演三联卡**（v4.10 起固定骨架，见下方「损失预演三联卡骨架」；标题固定写「损失预演」，禁止用英文 Pre-mortem）） |

| `valuation` | ✓ | **结构化三情景假设（必填，不完整拒渲染）**——脚本算出目标价区间/EPS/较现价/中枢/赔率/离散度，并自动生成 7 情景表+三指标卡+走廊图，target_range 不一致会被计算值覆盖：`{"shares":46.27,"horizon":"12个月","scenarios":[{"key":"pess","label":"悲观","trigger":"价格战重启","profit":850,"pe":[16,18]},{"key":"base","label":"基础","trigger":"出货+30%","profit":930,"pe":[22,25]},{"key":"opt","label":"乐观","trigger":"储能超级周期","profit":1000,"pe":[26,30]}]}`（shares 亿股、profit 归母净利亿元、pe 区间）。**必须含 pess/base/opt 三情景；每情景需 profit（净利）+ pe 区间 + horizon（可放情景级或 valuation 级）**。**口径二选一**：行业附录市值口径（NAV/rNPV/SOTP，见 `scoring.md`「市值口径三情景」节）每情景用 `"mcap":[低,高]`（目标总市值，亿元）替代 profit+pe——目标价 = mcap÷shares 脚本换算，情景表自动改显示「目标市值」行；三情景必须同口径、同情景不得双填，混用/双填/mcap 区间非法一律拒渲染；**shares ≤0、利润口径 PE 区间倒挂（高<低）或为负同样拒渲染**。**每情景 `trigger` 写 ≤15 字短语**（v4.10 起三情景表触发条件行随列右对齐，长句换行难看——工行「NIM 降至 1.22%、信用成本升至 0.65%」24 字实证）；情景表/目标价区间卡/走廊图的目标价由脚本统一展示（v4.10 起 <10 元两位小数、≥10 元整数，低价股区间不再被整数格式化压没） |

## 评分计算规则（脚本执行，模型不要手算）

- **质量层（L1/L3）**：层分 = Σ(维度分×层内权重) ÷ 100；不考虑风险质量分 = L1 层分×L1占比 + L3 层分×L3占比
- **1D 红旗扣分**：`red_deductions` 合计从 `scores["1D"]` 中先行扣减（下限 0），再参与 L1 层分计算
- **质量分（最终）** = 不考虑风险质量分 − 黄灯扣分合计（`yellow_deductions` 的 points 求和），下限 0
- **估值分** = 脚本按 `valuation_inputs` 四件套计算，无手填路径（公式与判读唯一权威见
  `scoring.md` 估值分节；`valuation_score` 字段的处理见顶层字段表）
- **时机分** = Σ(时机维度分×权重) ÷ 100（筹码面 67% + 技术面 33%）
- 各层内权重之和≠100、layer_share 之和≠100 → 脚本报错拒绝渲染
